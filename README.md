# Blockchain Champ (бывший ATLANT Hub)

**Blockchain Champ** — это интерактивная образовательная платформа для подготовки к чемпионату по блокчейн-технологиям. Проект построен на современных веб-технологиях и работает по принципу Serverless-архитектуры: все обучающие материалы (конспекты, тесты, кейсы) хранятся в открытом репозитории на GitHub, а сайт динамически подтягивает их по API.

---

## 🚀 Основные фичи (Features)

1. **Интерактивный Роадмап (Roadmap)**
   - Главная страница приложения, представляющая собой карту знаний.
   - Узлы (ноды) роадмапа строятся на основе структуры папок в GitHub (например, `info/solidity`).
   - Отображается количество конспектов внутри каждого раздела и индикатор прогресса (прочитанные конспекты).

2. **Serverless Content (Синхронизация с GitHub)**
   - Проект не имеет собственной базы данных. При первой загрузке или нажатии кнопки «Обновить» (`Sync`) приложение стучится в GitHub API (`/git/trees/main`) и выкачивает актуальное дерево файлов Markdown.
   - Материалы хранятся в `localStorage` браузера для моментальной загрузки.

3. **Отслеживание прогресса и закладки**
   - Каждый прочитанный конспект помечается галочкой.
   - Пользователь может добавлять конспекты в **Закладки** для быстрого доступа.
   - Весь прогресс сохраняется локально. Во вкладке «Прогресс» можно скачать файл-бэкап (`JSON`) и восстановить его на другом устройстве.

4. **Тестирование (Interactive Quiz)**
   - Раздел тестов генерируется на основе `.json` файлов из папки `test/`.
   - Поддерживает систему ввода ответов текстом (сверка происходит без учета регистра).

5. **Темная и Светлая темы**
   - Нативная поддержка переключения тем через CSS Variables (`var(--bg)`, `var(--tx)` и т.д.).
   - Состояние темы запоминается в браузере.

6. **Поиск (Command + K / Ctrl + K)**
   - Полнотекстовый поиск по загруженным конспектам, заголовкам и разделам роадмапа.

## 🏗 Архитектура и структура файлов

Проект написан на **React + Vite** без использования тяжелых фреймворков вроде Next.js, что позволяет бесплатно и быстро хостить его на Vercel или GitHub Pages.

### Дерево проекта (основные директории)

```text
src/
├── core/                  # Ядро приложения: логика, кэш, API
│   ├── api.js             # Взаимодействие с GitHub API (загрузка структуры, markdown, json)
│   ├── cache.js           # Управление localStorage (очистка, сохранение слепков)
│   ├── config.js          # Глобальный конфиг (ссылка на репозиторий, cacheVersion)
│   ├── context/
│   │   └── AppContext.jsx # Глобальное состояние (React Context) - хранит прогресс, разделы
│   └── progress.js        # Логика отметки "изучено" и "в закладки"
│
├── styles/
│   └── global.css         # Вся стилизация. Никакого Tailwind! 
│                          # Только чистый CSS с использованием переменных (CSS Variables) для адаптации под светлую/темную темы.
│
├── ui/                    # UI Компоненты и Страницы
│   ├── components/
│   │   ├── Header.jsx     # Верхняя панель навигации (логотип, поиск, смена темы)
│   │   ├── SearchModal.jsx# Модальное окно поиска (Ctrl+K)
│   │   └── Icons.jsx      # SVG иконки
│   │
│   └── pages/
│       ├── RoadmapPage.jsx# Отрисовка SVG-карты с узлами (RmNode)
│       ├── SectionHub.jsx # Список конспектов внутри конкретного раздела
│       ├── ChapterPage.jsx# Страница чтения Markdown-конспекта
│       ├── QuizPage.jsx   # Страница прохождения тестов (free-text input)
│       ├── BookmarksPage.jsx # Страница закладок
│       └── ProgressPage.jsx  # Дашборд прогресса, скачивание и загрузка бэкапов
│
├── App.jsx                # Настройка React Router (маршрутизация)
└── main.jsx               # Точка входа в React-приложение
```

## 🛠 Как работают основные механизмы

### 1. Как добавлять новые материалы?
Никакой админки нет. Чтобы добавить конспект, достаточно просто запушить `.md` файл в репозиторий с материалами (например, в папку `info/solidity`). Сайт автоматически увидит новый файл, если сбросить кэш (кнопка обновить в хэдере).

### 2. Управление кэшем (`cacheVersion`)
Из-за жесткого кэширования в браузерах и API GitHub, в файле `config.js` есть константа `cacheVersion`.
Если разработчик меняет логику парсинга или хочет принудительно заставить всех пользователей скачать свежие данные, он просто увеличивает этот номер (например, с `1.0.2` на `1.0.3`). Сайт при загрузке сравнит версии и, если они разные, сотрет `localStorage`.

### 3. Парсинг Markdown
Конспекты пишутся на обычном Markdown. Внутри компонента `ChapterPage.jsx` текст преобразуется в HTML. Встроенная подсветка синтаксиса для блоков кода работает через регулярные выражения (кастомный микро-парсер в `global.css`), чтобы не тянуть тяжелые библиотеки.

### 4. Дизайн Роадмапа
Карта разделов строится математически в `RoadmapPage.jsx`. Задаются координаты `(x, y)` для каждого раздела. Соединительные линии (SVG path) рисуются автоматически от одного узла к другому, учитывая их позицию на экране. При наведении мышки линии подсвечиваются.

## 💻 Сборка и деплой
- **Установка зависимостей:** `npm install`
- **Запуск для разработки:** `npm run dev`
- **Сборка для продакшена:** `npm run build`
- Для деплоя на Vercel достаточно привязать GitHub репозиторий, Vercel сам выполнит `npm install` и `npm run build`. Папка сборки по умолчанию — `dist`.
